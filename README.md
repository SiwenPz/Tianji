# 天机 (Tianji)

> 手里有什么牌,都能打。

天机是一个多 AI 助手编排工具:把你手里的命令行 AI 助手(Claude Code、codex、deepseek-harness、atomcode、kimi、cline……)组织成一支有分工的队伍,跑完接单、讨论、计划、分配、执行、审核、返修、归档的完整流程。不挑壳、不挑模型,什么都能接。

## 有什么用

你手上可能有这些东西:免费档的 key、能力一般的小模型、杂牌壳、快过期的额度。单个看不上,放着吃灰。天机把它们拼成一支队伍:

- **按实测派活**:每个"壳+key+模型"组合有表现分,按真实干活成绩排队。小模型派简单活,好模型干难活、当审核员
- **一壳多开**:同一个壳挂不同 key,开几个实例当几个工人
- **质量档位明说**:每个组合标注成色(不同 key 不同壳最好,同壳同 key 最差),不坑你
- **一个 key 也能跑**:全流程照跑,质量降级(自己干自己审),装的时候会直说
- **随时加新壳新 key**:新壳照"八问检查单"走一遍就能接进来

## 纪律交给机器,不靠自觉

多助手协作的老问题是没人管纪律:助手说"做完了"没人核实,卡住了没人发现。天机的做法:

- **完工只认结算单**:工人向账本提交 `worker_done`(带身份令牌,一次事务,重复提交不重复执行)。没结算就是没干完
- **监控只认客观信号**:文件字节涨不涨、事件来不来、进程活没活。只判信号不猜原因,宁可误报不误杀
- **一切状态一本账**:SQLite 单文件,账本 CLI 是唯一写入口,非法状态转换直接拒绝。出了事翻账本能还原现场
- **审核双轴交叉**:两个不同实例、不同模型后端分别审"照没照规格做"和"活干得好不好",再由架构师裁判,最后你点头才归档

顺手的细节:

- 工人干不动可以发 `worker_help` 喊救命,不用死撑到超时
- 审核驳回自动重派,任务书自动带上上轮驳回原因,工人知道前一轮差在哪
- 卡住被误标"停滞"可以复活(`dispatch revive`);总控 secret 丢了有恢复通道(`controller-recover`)
- git 项目自动给每个任务开独立 worktree,工人并行互不干扰,你确认后机械合并回主分支

## 快速开始

```bash
# 需要 Python 3.9+
pip install git+https://github.com/SiwenPz/Tianji.git
# 或下载 Releases 的 zip,解压后 pip install .

# 就这一条命令: 建账、起常驻服务、自动打开浏览器进配置页
tianji start
```

配置页里纯点选,不用敲命令:

1. **选总控**:下拉自动列出本机已装的 AI 助手(Claude Code / codex / kimi / atomcode / cline)
2. **配实例**:每个助手选模型来源——自带/内置(免 key)或外接模型服务(填 key+地址,点"探测"自动列出可用模型);定角色(审核/实施)和开几个
3. 编制总览实时生长,一行一个实例;审核没配齐双轴会当场标红提醒
4. 点"配齐了,去开工"→ 进驾驶舱,直接跟总控说话(流式回复、思维链可见)

之后干活全在驾驶舱 `http://127.0.0.1:8787`;习惯终端的也可以用 `tianji console` 开同一个总控会话。换 key/模型不用重建实例:`tianji instance update <名字> --model ...`,换 key 本体只需覆盖 key 文件。

## 它是怎么工作的

```
        用户
         │ 唯一交互面
         ▼
       总控(你的主会话)
         │ 建任务/批计划/最终确认
         ▼
   ┌──────────┐   派单(带任务书+身份令牌)   ┌──────────┐
   │  分配器   │ ────────────────────────▶ │  实施者   │(可多个,按表现分选)
   └──────────┘                            └──────────┘
         ▲                                       │ worker_done 结算
         │                                       ▼
   ┌──────────┐   验收不通过=驳回重派      ┌──────────┐
   │  监控器   │ ◀──活性对账(字节/事件/进程)│  审核者   │(双轴交叉审核)
   └──────────┘                            └──────────┘
         │                                       │
         └────────── 账本(SQLite,单一真源)──────────┘
```

任务走九态状态机(新建→讨论→待确认→已派单→执行中→审核中→待确认→已归档,另可重开);派单走七态(发出→开工→结算/卡住/重派/升级/取消)。消息、游标、幂等回执、审计,全在同一本账里。

## 当前状态(v0.6.0)

这套框架是**用自己管理自己的方式(自举)开发出来的**——上面的流程不是 PPT,是真实跑过很多遍的流水线:已完成的功能票(双轴审核、worktree 原语、壳模板、能力分配、daemon 守护……)全部由天机自己派单、自己审核、自己归档。

已经能用:

- **`tianji start` 一键起步**:终端零问答,配置全在 web 页纯点选(扫描本机助手/探测模型清单/角色个数/编制总览)
- **驾驶舱 Web 完整页**:四桶快照+审批+升级卡;**总控窗格=真会话**(claude 常驻双向流,打字机+思维链+工具调用可见);`tianji console` 终端入口可选
- 账本 CLI 全命令面(任务/派单/消息/实例/配置/验收/监控/驾驶舱快照)
- 任务九态 + 派单七态状态机、16 种消息、游标 + 幂等
- 双轴审核(Spec 轴+质量轴)+ 架构师裁判 + 最终确认闸门(最小配置可单实例串行降级)
- 任务级 git worktree 隔离与最终确认后机械合并
- 能力画像与分配算法(硬过滤+表现分软排序+expect_min 分档)
- 壳接入模板机制 + 档 2 转录解析公共框架(内置 claude/codex/kimi/atomcode/cline 模板)
- 工人求助(worker_help)、停滞续推(nudge)、强制干预(派单取消/改派/复活)
- 实例四元数据模型(壳+key+模型+隔离目录)、组合合法性机械校验、实例增删改
- 监控器活性增强(断网模式/后台任务判活/按壳字节源/无钩子壳三层证据)
- **daemon 守护**:`tianji daemon start/stop/status` 统一拉起监控器+驾驶舱 Web,崩溃自动重拉;每日账本备份+保留轮换
- 权限框架(总控审批双入口)、动态阈值校准、额度健康度、上下文卫生、钩子分发对账、主题插件、组合红黑榜、显示模式与思考级别

在路上的:非 claude 壳的 web 总控真会话、新壳模板(如 dsh)、SSE 推送(当前 1.5s 轮询)。

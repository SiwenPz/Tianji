# domain-modeling(领域语言)— 归口: 架构师

机制事实的唯一家是账本与规格书;本技能只管"叫什么、怎么定义"。

## 步骤

1. 讨论中敲定一个概念时,记录: 术语、定义、边界(它不是什么)。
2. 架构裁决(为什么这么定)另记一条,带日期与触发场景。
3. 后续产出(票名/任务书/报告)用词与词汇表对齐;要造新词先回头查表。
4. 与既有裁决冲突时,明说"与某条冲突",不停下来偷偷覆盖。

## 完成判据(逐条可检验)

- 新概念在领域文档里查得到定义与边界。
- 新产出引用的术语与词汇表一致,无同义漂移。

## 防提前完成

- "大家懂就行"不算沉淀;写进文档才算。
- 只记结论不记边界的条目视为未完成,补边界。

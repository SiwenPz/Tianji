# to-spec(写规格)— 归口: 架构师

规格书是实现的唯一依据;规格没写的,实现不许发挥。

## 步骤

1. 只写机制决策: 状态/字段/校验/时序;不写目标口号。
2. 每条标注出处(哪轮讨论的哪个裁决)。
3. 与既有条款冲突时,改旧条并注明修订原因,不并存两套说法。
4. 写完呈用户: **点头才算定稿**,未点头不许拆票;点头与修订记录落账本审计。

## 完成判据(逐条可检验)

- 每条规格可被"照做/没照做"机械判定。
- 用户明确点头记录在案。

## 防提前完成

- "大概这么设计"不算规格;能据此验收才算。
- 发现实现期绕过规格的发挥,停下来回写规格再动。

# code-review(双轴审核)— 归口: 审核者

审核不是读后感;每条结论都要有行为证据指得着。

## 步骤

1. 读任务书的"被审对象"节: 被审派单、产物目录、实施者报告、你的审核轴。
2. 按轴审:
   - **Spec 轴**: 任务书验收标准逐条勾选,每条附证据(命令输出/文件/账本行)。
   - **质量轴**: 按账本 quality_axis_checklist 六维逐项核查;挑 1-2 个报告声称的数据点独立复现交叉核对。
3. 非 git 项目: 改动边界声明降级为人工核对项,逐路径核对是否越界。
4. 写审核报告到你的报告路径,结论=pass 或 reject(附原因)。
5. 结算: `tianji dispatch settle <dispatch_id> "<报告路径>" pass|reject`。

## 完成判据(逐条可检验)

- 每条验收标准/每个维度都有"过/不过+证据",无"略"。
- 交叉核对的数据点是审核者独立复现的,不是照抄报告。

## 防提前完成

- 没跑验收命令就引用"全绿"=虚假声称,直接 reject 自己这轮重来。
- pass 的每一条都要能指着证据;指不着的按不过处理。

# new-shell-onboarding(新壳接入)— 归口: 总控

新壳来了照单问,不问完不入库。各壳核查答案=数据,入账本(壳条目+实例档案),不写进文档。

## 八问检查单(规格书 6.7,逐问答全)

1. **档 1 钩子**: 有无原生钩子?事件覆盖公共 8 类(session_start/session_end/stop/user_prompt/pre_tool_use/post_tool_use/permission_request/subagent_start/subagent_stop)中哪几类?有无会话结束事件?
2. **档 2 状态文件**: 位置/格式/更新时机/带不带 usage?
3. **档 3 无头**: 无头模式怎么跑?多实例隔离方式是什么?
4. **provider 绑定类型**: env 注入型还是壳内配置型(决定启动器生成方式)?
5. **后端协议清单**: 支持哪些协议(写进壳条目 protocols 字段)?
6. **权限拦截方式与无头默认行为**: 钩子 allow / 规则表 / 大类开关?无头是放行还是挂起?
7. **session_end 事件映射**: 哪个事件算会话结束?没有就档 2+档 3 兜底。
8. **思考级别怎么设**: 低/中/高三档映射到该壳哪个原生参数?不支持就如实记实例档案。

## 产物五样(全走现成机制)

壳条目(`tianji config shell set`)+ 适配器脚本(套用内置壳模板)+ 钩子安装 + 应然清单条目 + 能力画像建档(标"待实测")。与动态新增同套增量流程(`tianji wizard add`)。

## 三关自测(fail-loud,哪关不过停哪关)

1. **模拟事件全链路**: 钩子→适配器→`tianji ingest-event`→账本事件行可查。
2. **真会话 spawn**: `tianji spawn <实例> <派单>` 拉起,登记行回填 active。
3. **(可选但推荐)最小真实任务闭环**: 派一单小活,走完 结算→验收→审核;过了才摘"待实测"。

## 完成判据(逐条可检验)

- 八问答案全部入账(壳条目/实例档案可查)。
- 三关全绿,各有账本或命令输出证据。
- 画像"待实测"标注与实情一致。

## 防提前完成

- 任何一问"应该支持吧"=没答;实测或实测不到就记"不支持"。
- 自测三关缺证据不算过,不许先接活后补票。

# new-shell-onboarding(新壳接入)— 归口: 总控

新壳来了照单问,不问完不入库。各壳核查答案=数据,入账本(壳条目+实例档案),不写进文档。

## 八问检查单(规格书 6.7,逐问答全)

1. **档 1 钩子**: 有无原生钩子?事件覆盖公共 8 类(session_start/session_end/stop/user_prompt/pre_tool_use/post_tool_use/permission_request/subagent_start/subagent_stop)中哪几类?有无会话结束事件?
2. **档 2 状态文件**: 位置/格式/更新时机/带不带 usage?
3. **档 3 无头**: 无头模式怎么跑?多实例隔离方式是什么?
4. **provider 绑定类型**: env 注入型还是壳内配置型(决定启动器生成方式)?
5. **后端协议清单**: 支持哪些协议(写进壳条目 protocols 字段)?
6. **权限拦截方式与无头默认行为**: 钩子 allow / 规则表 / 大类开关?无头是放行还是挂起?
7. **session_end 事件映射**: 哪个事件算会话结束?没有就档 2+档 3 兜底。
8. **思考级别怎么设**: 低/中/高三档映射到该壳哪个原生参数?不支持就如实记实例档案。

> ⚠ 两个"协议"轴不许混: 问 5 的"后端协议清单"是**模型 API 协议**
> (key 对哪个 LLM 端点,如 anthropic/openai);下面 ctrl_session 一节的
> "会话协议"是**总控与壳子进程通信**的协议(如 stream-json/ACP)。
> 两轴各入各的字段。

## 顺手填: 壳条目的 ctrl_session 块(可选,不是门槛)

八问管的是"能不能进编制干活",入库只看八问三关,不看这节。
壳条目里另有一个可选 `ctrl_session` 块(规格书 13.2): 这壳要是有
可编程的双向流式会话接口,顺手把下面四项填进块里,它就能当总控
(web 驾驶舱真会话本体,15.5);没有这种接口就不填,不挡入库,
只是暂不能当总控。

1. **会话协议**: 有没有可编程的双向会话接口?对哪个协议 backend——
   ACP(JSON-RPC over stdio,kimi/cursor-agent 这类)→ 复用 `acp`;
   claude 式 stream-json 自循环 → 复用 `stream-json`;都不是=暂不能当总控,
   如实记"仅工人",不硬接。
2. **拉起命令**: 无头/协议模式的完整命令(如 `kimi acp`)。
3. **数据根重定向**: 有没有整体重定向数据根的环境变量(如 KIMI_CODE_HOME)?
   有则总控实例隔离靠它;没有就如实记,登录态/配置与用户全局共享。
4. **key 注入方式**: 无头模式下 key 怎么进进程(env 家族名/配置文件)?
   对应 `_KEY_ENV_MAPPERS` 里哪个 style;现有 style 都不适用就新增一行
   mapper(这是唯一允许加代码的地方,backend class 不许动)。

> 口径: 协议 backend 写一次,壳条目声明差异。第三个 ACP 壳接进来=
> 填条目数据,零行新通信代码(票 29 验收 10)。

## 产物五样(全走现成机制)

壳条目(`tianji config shell set`)+ 适配器脚本(套用内置壳模板)+ 钩子安装 + 应然清单条目 + 能力画像建档(标"待实测")。与动态新增同套增量流程(`tianji wizard add`)。

## 三关自测(fail-loud,哪关不过停哪关)

1. **模拟事件全链路**: 钩子→适配器→`tianji ingest-event`→账本事件行可查。
2. **真会话 spawn**: `tianji spawn <实例> <派单>` 拉起,登记行回填 active。
3. **(可选但推荐)最小真实任务闭环**: 派一单小活,走完 结算→验收→审核;过了才摘"待实测"。

## 完成判据(逐条可检验)

- 八问答案全部入账(壳条目/实例档案可查)。
- 三关全绿,各有账本或命令输出证据。
- 画像"待实测"标注与实情一致。

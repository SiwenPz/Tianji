## 背景

spec 4.4 新口径（2026-08-25 用户裁决）：保留强制干预的**通用兜底跳转**（总控可把任务转到任意合法状态），但这条兜底通道**必须经人审批（HITL）**——总控发起任意跳转时，机械生成审批请求进账本待裁决，由用户显式批准后才执行；未经用户批准不得生效。

三种既定动作（强制终止/接管/改派）维持总控直接执行+审计，**不受此 HITL 门约束**。

现状锚点：`tianji/ops.py:1283` `task_force()`——通用 fallback（to_state 是三种既定动作之外的目标态时直接执行、无审批；`if to_state not in FORCE_TARGETS` 分支在 1302 行附近）。`FORCE_TARGETS` 定义在 `tianji/state.py`。

## 工作块

1. **账本审批通道**：兜底跳转的"待审批"请求落账本（复用现有 permission_rulings 还是新表/新消息，实现期定；原则=机械门 + 用户显式批准 + 审计）。
2. **task_force 改造**：目标态是三种既定动作（终止→archived / 接管→dispatched / 改派→dispatched）之外时，不走直接执行，改为机械落"待用户审批"请求。
3. **用户批准通道**：CLI 批准/撤销；发起人须总控、批准人须用户（HITL 语义），身份校验不放松。
4. **超时未批不生效**（不悬置账本）：过期请求自动失效或标记，不永久挂着。
5. **驾驶舱前端**：待审批卡展示（若 34 已合并，落进新三栏的中栏气泡流；未合并则按现有页面风格加卡，位置从简）。
6. **测试**：既定动作不弹审批、兜底跳转必弹、批准后生效、未批不生效、超时失效、身份校验（发起人非总控/批准人非用户都拒绝）。

## 验收标准

- [ ] 三种既定动作（终止/接管/改派）维持总控直接执行+审计，不弹审批
- [ ] 兜底跳转（目标态是三种之外）时：总控发起→机械落"待审批"请求进账本→用户显式批准→才执行迁移；未批准不生效
- [ ] 审批请求可审计、可撤销、超时未批不生效（不悬置账本）
- [ ] 身份校验不放松：发起人须总控，批准人须用户（HITL 语义）
- [ ] 全量 `python -m pytest tests -q` 全绿

## 红线

- 机械门语义：请求由机械规则生成（总控发起兜底跳转就落请求），不带任何"智能判断要不要审"。
- 身份校验 fail-closed：校验不过=拒绝，不降级放行。
- 账本是唯一写入口，审批状态全落账本可审计。
- 简洁优先、精准修改。
- 注释、文档一律大白话。

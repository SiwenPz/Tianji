# 任务书模板

> 这张模板是**派工自检三问**的载体：**路线、停止判据、用途**三样缺一，任务书不合格。
> 缺了它们，工人不会来问你，它会自己发明一条路线——而它发明的那条一定是"把许可范围从头扫一遍"。
> 实测对照（2026-09-16，同一任务、同一模型，唯一变量就是任务书）：
> 按老模板（只有目标 / 交付物 / 红线）→ 一席 **83 次工具调用**、9 分钟只交出六分之一被掐；
> 按这份模板 → 三席并行、**4 / 11 / 12 次调用**、**2 分 49 秒**全部交付。

<!-- **多个席位共用的事实（规模 / 版本 / 清单 / 环境），由派工者测一次写在这里**，各席直接引用。

## 每节完成判据（必填）

<!-- 写死"本节 ≥N 行 + ≥M 条 `文件:行号`，达到即**封版**，不许为了更全再读"。
     没有停止判据的工人不会停，预算只能限制它停得多难看。
     判据必须**能被产物结构满足**——写下限前先数一遍（实测踩过：给一张 33 行的表写"≤35 行"，
      而 33 个文件 + 表头 3 行 = 36，工人只能二选一，两种都不是你要的）。
      同一把尺子也量必查项：**必查项 + 强制落盘必须装得进预算**，装不下就砍范围或补席
      ——别让工人自己二选一（实测：预算用尽后 3 个必查项直接没做 ✗）。 -->

## 预算（必填）

<!-- 三样一起写：
     ① 宿主轮数上限（晨检 `[INFO] 子代理轮次上限` 里能读到）
     ② 目标工具调用次数上限
     ③ **时间预算**："这一席最多跑 N 分钟，到点由总控掐断，成果以落盘为准"。
     只有 ①② 卡不住墙钟：实测一次审核席**只用了 7 次工具调用、48k token，却跑了 11 分钟**
     ——席位墙钟 ≈ 步数 × 每步延迟，而质量档模型的每步延迟可达 ~1 分钟，中间还夹着一段
     等后台命令的静默挂死。到预算就**封版交稿**：先交一份不全的，比交不出来强。
     **撞上限 = 半成品**：回执写"hit its turn limit"的产出不许当交付收口——
     要么改小边界重派，要么补席。
     **调用预算要先把强制动作扣掉**：强制落盘与回执不是取证，不计入 N 次（实测不扣的两席
     各超 1–2 次 ✗）。**必查项没做完 = 回执第 1 行 fail-loud 写明"必查项 X/Y 未完成"**
     ——不许埋在"剩余风险"里让派工者自己翻 ✗。 时间预算不止写在任务书里，**开单时必须用 `--time-budget` 落账**，否则底栏和收口都看不见它。**预算三样：时间 / token / 调用次数**，调用次数用 `--call-budget N` 落账。 -->

## 证据档位（必填）

<!-- 三档，写进交付物里逐条标注：
     实证   = 我读到的行 / 我跑的命令
     文档   = 引 `文件:行号` 并写明"据文档"
     未核实 = 显式标注，不许留空默认为已证
     要求"全篇实证" = 逼工人把预算烧成一个人的全量复核（实测：45 次 read_file 只交出一节）。
     反过来，文档级引用**不许伪装成已验证**——它会错（实测照 HANDOFF 写了个这仓库根本
     不存在的模块 `app/cli.py`），写明"据文档"正是为了让读者知道该核哪几条。

     **数字必须带口径**：我数了什么、跳过了什么。没写口径的数字不算证据——实测一席数得
     "磁盘 = 追踪 = 7412"，据此断言"没有未追踪的残渣"，而它恰好把残渣排除在统计之外
     （177 个 `.tsbuildinfo`、1,560 个 `.map` 在磁盘上、0 个入库）✗。
     **结论不得超出证据**：一条命令只支撑它直接测到的那件事；写完自问"这组数**不能**说明什么"。
     **行号不许估**：只有两种合法形态——从读出的片段/命令输出里**粘**出来，或写"未核实(位置未定)"；
     估的行号一律不算证据 ✗（实测一席给 `configs/dev.yaml:396,402`、实为 `:40,46` ✗）。
     **聚合数字要能被复核方复现同一个数**：写明数的是哪个集合、怎么采、排除了什么；
     方法不同会得到不同数时（实测同一份 lineage：115/77 vs 145 ✗），必须写明方法边界。 -->

## 耗时命令的唯一形态（必填）

<!-- 长命令（测试 / 全量扫描）：前台跑一次；或后台起一次后**带着时限**等它。
     **禁止**反复 `type` 日志、**禁止** `tasklist` 探活、**禁止**因没看到结果就再跑一遍
     ——实测这三样合起来烧掉约 1/4 预算。跑之前先把别的节写完，别让交付物卡在一条命令上。
     **"等它"必须有时限**：这台宿主会把长命令自动转入后台，而后台日志**可能是 0 字节**
     （实测：后台跑 pytest 得到一个空日志文件），一条不设时限的 wait 会让席位静默挂到被掐。
     规则：wait 带超时（≤120 秒）→ 超时后直读日志尾部一次 → 还是空的就放弃该命令并如实标
     "未取到输出"，不许再等、不许重跑。

     **宿主手别抖（Windows + cmd 上实测踩过的三样）**：① 没有 `<<'EOF'` heredoc —— 提交信息先
     写进文件，再 `git commit -F <文件>`；② 没有 `head` —— 要截断就用 python 或 `findstr`；
     ③ **长命令接 `| more` 会把输出卡死、日志变成 0 字节**（实测：后台跑 pytest 得到空日志，
     看起来像"没有内容"）—— 要么前台直接跑，要么重定向到文件。这三条派工者自己踩过，工人
     一样会踩。 -->

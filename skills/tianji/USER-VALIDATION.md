# 天机用户黑盒验收

这不是让用户执行脚本的开发者测试。安装并重新加载宿主后，用户只发一条正常任务：

> 天机，请检查当前项目的一个小功能，修复发现的问题，补充或更新测试，并运行相关测试后汇报。

天机内部必须自动完成晨检、模型和路由证明、角色派发、修改、机械验收、失败补偿和账本记录。用户不需要输入 Python 命令，也不需要手动指定 worker、verifier 或验收脚本。

## 用户可见的成功标准

- 天机先给出简短计划，然后开始工作；
- 实际使用已配置并被证明的模型和宿主角色；
- 修改真实落盘，测试真实执行；
- 测试未通过时自动返工，不把失败伪装成成功；
- 最终汇报修改文件、执行的测试、结果和剩余风险；
- 没有通过机械验收时不能说“已完成”。

## 用户可见的失败标准

出现以下任一情况都算天机不可用：

- 让用户自己运行晨检、探针、账本或验收 Python 命令；
- 只给方案不修改、不测试；
- worker 自称完成就跳过 verifier；
- 配置了模型但无法证明实际调用模型；
- 失败后无限重试或静默切换模型；
- 测试失败仍报告完成；
- 账本显示任务成功但没有对应命令和退出码证据。

## 故障场景

正常任务验证通过后，主会话可以在内部安排一次受控失败（例如运行一个预期失败的测试）来确认返工闭环。这个故障注入由天机自己完成，用户只观察它是否能说明失败、修复并重新验收，不需要执行任何脚本。
